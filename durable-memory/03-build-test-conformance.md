# Build, test and conformance

- **Build/test (g++ 11, C++17, no dependencies):** `make test` builds and runs `tests/dslvm_test.cpp` (57 checks: valid programs, int64 wraparound, sections,
  every verifier rejection, run-time checks and no-limit pins; an in-test assembler crafts invalid files). `make conformance` builds
  `conformance/run.cpp` and runs it over `conformance/vectors` (24 vectors in the current S1' set). Both take seconds. Use
  `nice -n 10 make ...` on the shared box.
- **Vectors are generated by the lmscript compiler, not written by hand:** lmctl-mono
  `node --experimental-strip-types lmscript/scripts/generate-dsl-conformance.ts OUT_DIR` writes `schema.json`, `schema-extra.json`,
  `NAME.dsl` (source), `NAME.dslb` (bytecode), `NAME.expect` (line 1 `trace` | `runtime_error` | `load_error`, then the expected
  lines or the error substring) and `manifest.json`. The mono test `tests/dsl-conformance.test.ts` keeps the generator complete
  (every opcode appears), deterministic and consistent. Regenerate into `conformance/vectors` and commit when the compiler changes.
- **What a runtime must implement to run the vectors** (`manifest.json` "host"): context `t` of type `Trace` recording one line
  per call (`int N`, `float %.15g`, `str S`, `bool true|false`, `thing ID`), context `root` = Thing id 0, `thing(i)`,
  `Thing.id/next/name/scaled`, `twice(i)`, `half(f)`, `yes()` (records `yes`, returns true), `fail(s)` throws. Nothing is
  C++-specific; a Rust runtime (R21) reads the same files.
- **Where the SDK version is checked:** `dslvm::VERSION` (4). The compiler's `DSL_VERSION` in `lmscript/dsl.ts` must equal it;
  the vector `load-other-version` proves the loader refuses an older version (including v3).
